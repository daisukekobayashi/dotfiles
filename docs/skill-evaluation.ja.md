# Codex・Claude Codeでのスキル評価

`evaluate-skill` を呼ぶと、エージェントが課題の選定、分離した環境での候補実行、
採点、結果の整理まで進めます。`pstack` profile に含まれ、Codex・Claude Codeで
同じ本文を使います。

```text
Codex:       $evaluate-skill maintain-verification-skill
Claude Code: /evaluate-skill maintain-verification-skill
```

既定では呼び出した側のエージェントで評価します。両方を評価したい場合は、
「CodexとClaudeの両方で」と指定します。それぞれのエージェント内で
「スキルなし／あり」または「旧版／新版」を比較し、モデル・設定・権限・ツール・
初期ファイルを揃えます。モデル差をスキルの効果と混同しません。

## スキル内の役割

- [SKILL.md](../skills/local/evaluate-skill/SKILL.md): 評価条件、候補の実行、採点、結果の整理を指示する入口。
- [実行手順](../skills/local/evaluate-skill/references/execution.md): ケース形式、両CLIでの実行方法、証拠と採点形式。
- `scripts/prepare.py`: スキルに同梱した環境準備用の補助。必要に応じてエージェントが実行する。

ユーザーが外部の準備コマンドを実行する必要はありません。エージェントが利用可能な
独立セッションやCLIで候補を実行し、実際のコマンド出力・変更内容・成果物を確認します。
主観的な比較は条件名を伏せた独立した評価者に渡します。独立した評価者を使えない場合は、
進行役自身による評価と明記します。

補助スクリプト自体は環境を準備するだけです。モデルの実行・採点はスキルが進める
別工程で、利用できない認証・権限・実行機能があれば未完了の範囲を報告します。
評価だけで対象スキルを自動修正することはありません。

## 課題と検証範囲

再利用する課題は対象スキルの `evals/evals.json` に置きます。
`maintain-verification-skill` には次の3ケースがあります。

| ID | 状況 | 確認すること |
|---|---|---|
| 1 | 検証コマンドが古い | 現行コマンドへ更新し、期待値を保って実行確認する。 |
| 2 | 製品コードが仕様に反する | 本体や期待値を変更せず、不具合と失敗の証拠を報告する。 |
| 3 | 一部機能の利用条件が欠ける | 試した経路と不足条件を示し、全体を検証済みとしない。 |

実行記録・採点結果・条件名との対応表は `/tmp` または無視対象の作業場所に保存します。
少数の課題から一般的な優劣は断定せず、不足する証拠や未実行も結果に残します。

`bats tests/setup_pstack_skills.bats tests/skill_evals.bats` は両エージェント向けの
配置と準備処理を確認します。実モデルでの有効性を証明するものではありません。
通常のスキル発見・起動も、本文を与えた場合の成果比較とは別に確認します。
